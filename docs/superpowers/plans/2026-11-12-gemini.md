# Gemini images: measured facts and plan (2026-11-12)

Approved by the owner on 2026-11-11 ("làm hết": ChatGPT, then Gemini; Grok was dropped on 2026-11-12). Same shape as ChatGPT
([2026-11-11-p5-chatgpt.md](2026-11-11-p5-chatgpt.md)): **prompt → image**, one new conversation per batch, prompts sent one after another, each image saved by the app. Not in this version: reference images, choosing the aspect ratio or the model from the app (the page has both controls; the batch runs with what is selected in Gemini), Gemini on the Workflow canvas or through MCP.

## Measured on the live page (account `Quang Ng`, Pro, Vietnamese UI, Chrome profile `ng***`)

Tools: `apps/extension/gem-ops.js`, `SITE=gem npm run live-gpt -w apps/desktop` (ops in order, structure only), `SITE=gem PROMPTS='a|b' npm run live-gpt-batch`.

- **Controls are found by icon name**, which does not change with the UI language (`mat-icon` / `gem-icon`: `fonticon`, `data-mat-icon-name`, `name` or its text). Input area = `input-area-v2`; editor = `rich-textarea .ql-editor` (Quill).
- **"+"**: the button with icon `plus`; a plain `.click()` opens a menu in `.cdk-overlay-pane`. The image tool is the `[role="menuitemcheckbox"]` with icon `image_create` (others: `movie`, `music`, `canvas`, `deep_research`).
- **Image tool on** = a chip in the input area: `[data-test-id="deselect-drawer-item-gem-button"]` holding the `image_create` icon. It **stays on after a send** (ChatGPT's pill does not). With it on, an aspect control appears (icon `aspect_ratio`) and the page shows a style gallery until the first send.
- **Typing**: focus, caret to the end, `document.execCommand('insertText', false, prompt)`. **An unsent draft comes back after a reload**: typing after it sent a doubled prompt in the spike, so the product never types into a non-empty editor (exactly the prompt already there is accepted).
- **Send**: the button with icon `arrow_upward`, present only when the editor has text; while an answer is generated the area shows a `stop` icon instead.
- **Conversation**: path `/app` (new) → `/app/<16 hex>` within about 4 s of the first send. New conversation = point the tab at `https://gemini.google.com/app`; reopen = `/app/<id>`. After a navigation the turns render a few seconds after `status: complete`.
- **Turn** = `div.conversation-container` with `id` = 16 hex (the response id is `message-content-id-r_<same id>`); children `user-query` and `model-response`. The prompt is in `user-query .query-text-line` (the other query elements carry extra hidden text).
- **State over time**: `pending-request` / `pending-response` → `model-response` → `generated-image > single-image[data-image-attachment-index]` with the image loading → image shown → `message-actions` appears and the `stop` icon goes. No early "complete" as on ChatGPT. Click → finished image: 9–14 s.
- **Image on the page is a preview** (`blob:` `img.image.loaded`, 1024x572). The page fetches it as `https://lh3.googleusercontent.com/rd-gg-dl/<token>=s1024-rw?alr=yes` (0.65 MB WebP, several times while the turn finishes); the content script cannot `fetch()` the page's blob.
- **Full size** comes only after the page's own button `download-generated-image-button button` (icon `download`) is pressed. The page then runs two `batchexecute` calls (up to 11 s for an image just made) and three fetches, each answer carrying the next address: `lh3.googleusercontent.com/gg-dl/<…>=d-I` (0.4 KB) → `work.fife.usercontent.google.com/rd-gg-dl/<…>=s0-d-I` (1 KB) → **`lh3.googleusercontent.com/rd-gg-dl/<~1300 chars>=s0-d-I?alr=yes`** = the PNG itself, 2752x1536, 6–9 MB. In a reopened conversation the path is `/rd-gg/` and the middle host `lh3.google.com`. Only the option tail tells the file from the preview: `s0` (original size) with `d` (download).
- **That address is readable from the content script** through a `PerformanceObserver` on `resource` entries (name + `encodedBodySize`; `performance.getEntries()` is useless on this page, its 250-entry buffer is full soon after load). A `fetch` of it without credentials returns the same PNG, so it needs no cookie.
- **What the page does with the bytes cannot be relied on**: it hands them to an iframe `sandbox="allow-scripts allow-downloads"` with a `data:` document, which starts a browser download of an opaque `blob:` (no referrer, `image/png`, `Gemini_Generated_Image_<id>.png`). Chrome lets a page start one such download per page load the user began (a real F5); the next ones never start, without any prompt. A navigation made by the extension does not lift it, and **the site setting "Automatic downloads" → allow `https://gemini.google.com` does not either** (the owner set it on 2026-11-12; measured before and after: still one per load), because the download comes from the sandboxed frame's opaque origin, not from the site.
- **`chrome.downloads.download({ filename })` loses its filename while the extension has an `onDeterminingFilename` listener**: the file landed in Downloads under the server's name (`upsampled_img_<n>.png`). The listener has to suggest the name itself.

## Design

- **Extension**: `gem-logic.js` (pure: ids, query ownership, which address is the full-size file, which download is the page's own copy), `gem-ops.js` (page: `gemState`, `gemMode`, `gemPrep`, `gemSend`, `gemTurns`, `gemLook`, internal `gemDownload`), `sw.js` (`gemTabs`, `gemNew`, `gemOpen`, `gemFetch`; `gptFront` serves both sites). Media id = `<turn id>-<n>`.
- **`gemFetch`**: the content script presses the page's download button and answers our service worker (only it) with the address of the full-size file as soon as the page has fetched it (wait up to 45 s; else `NO_FULL_SIZE`). The service worker checks the address (https, `lh<n>.googleusercontent.com`, `/rd-gg/` or `/rd-gg-dl/`, tail `=s0-d…`; else `SRC_NOT_ALLOWED` with the host only) and downloads it itself into `ToolFlow-tmp`, naming it when the browser asks. The copy the page may start by itself is cancelled and erased while this runs and for 15 s after. One request at a time. The address lives in memory only; no op returns it and nothing logs it.
- **Desktop**: no new runner. `createGptRunner({ provider: 'gemini' })` with `createExtGpt(server, 'gemini')`; `routeRunner(flow, gpt, gem)`; outputs are fetched from their own site's tab by the shape of the media id.
- **UI**: Tạo lô → Nền tảng → "Gemini (tạo ảnh)"; Kết nối shows whether a gemini.google.com tab is seen; hints name Gemini.

## Live record 2026-11-12

1. Spike: tool + prompt + send by hand-driven ops: image after 14 s. The prompt went out doubled (restored draft, see above).
2. First design (name the page's own download): two-prompt batch made both images, saved the first (9 205 714 bytes), the second never started. The owner allowed automatic downloads for the site; repeated: still one per page load. Cause found with a spy op (sandboxed frame, see above); design changed to the one above.
3. Second design, first cut: the address was matched by host and path only. A three-prompt batch saved image 2 as the PNG and images 1 and 3 as the 1024x572 WebP preview, which comes from the same host and path. The `=s0-d` tail was added to the check, with a test.
4. `SITE=gem live-gpt-batch`, three prompts, final code: `#1 ready` 24 s, `#2 ready` 24 s, `#3 ready` 37 s, one conversation, journal `prepare,intent,clicked,turn,ready` three times; three PNG 2752x1536 saved (6 083 513, 6 863 500, 8 110 186 bytes); nothing left in Downloads or `ToolFlow-tmp`.
5. Real app window (under xvfb) + the real tab: Kết nối showed "Đã thấy 1 tab gemini.google.com"; Tạo lô → Gemini → two prompts; both cards "Gemini · Ảnh … Đã lưu" 61 s after the batch was created; two PNG 2752x1536 (7 471 007, 8 403 377 bytes).
6. `gemFetch` on older images, seven page loads, two presses each: 13 of 14 saved. One `NO_FULL_SIZE` on the first press 5 s after a reload, not reproduced in the six loads after it.

Seen once, not explained: in the batch of item 3's first attempt, prompt 2 was sent and its turn stayed an empty answer (no image, no error, page not generating) until the script's time limit. A turn like that reads `in_progress` and the batch waits out the 10-minute generation deadline; it did not come back in the three batches after it.

Not tried live: more than one image per turn, a prompt Gemini refuses, a second Gemini tab, a UI language other than Vietnamese (controls are found by icon name, so none should matter).
