## Measured on the live page (account `ng***`, Vietnamese UI)

- **Balance 58 credits** (`nzlxg` → `[58,…]`); Flow shows "Bạn sắp dùng hết tín dụng". Cost line in the open settings panel ("Quá trình tạo sẽ tốn N tín dụng"), x1: Veo 3.1 - Lite **10**, Omni 1.2 Flash (720p, 8 s) **24**, Veo 3.1 - Quality **100** (send button turns into the credit warning); Fast was 20 in the spike. So at most five Lite sends: every live video send is planned.
- **Settings panel in Video mode**: `Hình ảnh | Video`, then the input type `Khung hình | Thành phần` (Frames | Ingredients; Ingredients without refs is text-to-video, there is no separate text mode), aspect `16:9 | 9:16`, the model menu, `x1..x4`. Omni 1.2 Flash adds `360p | 720p` and a length slider; Omni 1.1 Flash adds `4/6/8/10 giây`.
- **Model menu**: Omni 1.2 Flash (Flow's default), Omni 1.1 Flash, Veo 3.1 - Lite, Veo 3.1 - Fast, Veo 3.1 - Quality. Omni 1.1, Fast and Quality carry "Sẽ ngừng hoạt động vào ngày 5 thg 12"; that line is part of the menu item's text, so the exact-label pick refuses them (fails closed). The image and the video mode remember their own model.
- **§8.1 answered (tile ↔ media)**: a video tile is an `img` whose src is `flow.google.com/asb/<token>…`, with no `data-media-id` and no link carrying an id. The project listing (`Zzl0ze`) holds for each video media four content urls (`[5][5]`, `[5][10]`, `[7][0][8]`, `[7][5][0]`) on `lh3.googleusercontent.com/<token>=…` with **one and the same token**, and that token is the one in the tile's src (10 of 10 newest videos). `as29s` (Flow calls it right after a video finishes) answers with one media entry in the same layout. So: media id → token (from `as29s` / `Zzl0ze`, inside the page) → `flow.google.com/asb/<token>=mm,22,15` → MP4 through `chrome.downloads` (spike: needs the browser's cookies).
- The listing has 103 finished videos of this project (96 `veo_3_1_t2v_lite`, 3 `veo_3_1_i2v_lite`, …): the download path can be built and tested on them without spending anything.
- Already in the code from P1: `kind: 'video'` end to end, `parseVideoReceipt`, `parsePoll`, the attempt states `generating` and the `poll` event, caps for video, `YhhmEf` as a generate call in the observer. Missing: polls never reach the runner, the frame RPCs have no fixture and are refused, the settings op picks the model before the mode, nothing binds a video to a download, the UI offers no video settings.
