Scope is [docs/app/05-chatgpt-driver.md](../../app/05-chatgpt-driver.md) (approved by the owner on 2026-11-11: "làm hết", ChatGPT first, then Gemini, then Grok). First version: **prompt → image**, one batch = one new conversation, prompts sent one after another, results saved. Not in the first version: reference images, an aspect-ratio control (the composer has none: the ratio can only be asked for in the prompt text), a ChatGPT node on the Workflow canvas, ChatGPT through MCP.

## Measured on the live page (account `Quang Ng`, plan Free, English UI, Chrome profile `ng***`)

Spike tools: `apps/extension/gpt-ops.js` (content script on `https://chatgpt.com/*`), `npm run live-gpt -w apps/desktop` (`STEPS='[["op",{args}],…]'`, `WATCH=<s>`). One image was generated (16 s from the click to the finished turn).

- **Composer**: `form [contenteditable="true"]` (ProseMirror, `aria-label="Ask ChatGPT"`). Send = `form button[type="submit"]` (`aria-label="Send"`); it does not exist while the editor is empty and it is replaced by a stop button while a turn is generating. A plain `.click()` on it sends (no trusted event needed).
- **"+" menu**: `form button[aria-label="Add files and more"]`. It opens on a synthetic pointerdown/mousedown/pointerup/mouseup/click sequence (a bare `.click()` is not enough). Its items are plain `button`s with no role, text = label + description: "Add photos & files", "Add from library", **"Create image"**, "Web search", "Deep research", "Sketch", "Thinking", …
- **Image mode**: clicking "Create image" puts a pill inside the editor: `span[data-inline-selection-pill][data-system-hint-type="picture_v2"]`. That attribute is the postcondition to read. The pill is gone after every send: the mode must be chosen again for each prompt.
- **Typing**: focus the editor, caret to the end, `document.execCommand('insertText', false, prompt)`; the editor text without the pill's label equals the prompt.
- **New conversation**: the sidebar "New chat" is a `button[aria-label="New chat"]` (language dependent). Used instead: the service worker points the tab at `https://chatgpt.com/` (`gptNew`). The path is `/` until the first send, then `/c/<conversation uuid>` (through a short-lived `/c/local-chatgpt%3A<uuid>`).
- **Turns**: there is no `article`, no `data-message-author-role` in this UI. One exchange (user message + answer) is one `div[data-turn-key="<uuid>"]`; the key equals the user message's id. Inside: `[data-user-message-bubble]` (the prompt as shown, pill label first), `[data-talvt-turn-state="complete"]` when the answer is finished, `[data-chatgpt-search-message-ids]` once per message (first the user's id, then the assistant's).
- **Generated image**: `div[data-testid="generated-image-gallery"] button[data-testid="generated-image-preview"] > img[alt="Generated image N"]`. Its `src` is a `blob:https://chatgpt.com/…` URL (PNG, 1448x1086, 1.7 MB); the content script can `fetch()` it. A blob URL cannot be handed to another context, so a download needs the bytes turned into a `data:` URL inside the page first.
- After F5 the conversation is rendered lazily: the turn and its image show up a few seconds after `status: complete`.
- **Turn state over time** (`data-talvt-turn-state`, measured on four sends): right after the click the new turn reads `complete` with no image for 2–5 s, then `in_progress`, then the gallery appears with the image loading, then the image is shown, then `complete`. So "complete without an image" proves nothing until the answer was seen in progress.
- **Send button**: for a moment after the previous answer ends it stays `disabled` although the next prompt is already in the composer (seen once: the second prompt of a batch). It unlocks by itself.
- A new conversation's path is `/` at the click, the id shows up 1–5 s later; the conversation id and the turns must be read in one look, otherwise a tab moved in between pairs our turn with another chat's id.
- Leaving the conversation (start page) and going back to `/c/<id>` shows its turns and images again; an image of a conversation that is not on the page cannot be fetched (`NOT_FOUND`).
- **Background tab**: while the ChatGPT tab is not the active tab of its window (`document.visibilityState` is `hidden`), pressing "+" brings no menu items (`MODE_NOT_FOUND`); after `chrome.tabs.update(tab, { active: true })` the same op works. The window itself does not have to be focused (on Linux; a minimised or fully covered window on Windows may still count as hidden, which the runner reports as `GPT_TAB_HIDDEN`).
- Timing: click → finished image 17–26 s. Files: PNG 1448x1086, 1.7–2.6 MB.
- Signed-out pages show "Log in" / "Sign up for free" buttons and the same composer.

## Design (smallest complete version)

- **Extension** (`gpt-logic.js` pure + `gpt-ops.js` page + `sw.js`): `gptTabs`, `gptNew`, `gptOpen` (back to one of our conversations), `gptState`, `gptMode` (choose Create image, read the pill), `gptPrep` (types; never over the user's own text), `gptSend` (clicks only when the composer holds exactly the prompt in image mode; waits up to 10 s for a locked button), `gptTurns` (conversation id + per turn: key, state, whether its user bubble is exactly the given prompt, ids of its shown images), `gptFetch` (the page hands the image's bytes as a `data:image/…` URL to `chrome.downloads`), `gptLook` (structure only, for diagnosing a changed page). Media id of image N of an assistant message = `<message uuid>-<N>`.
- **Desktop**: `src/main/gpt-runner.ts`, a runner of its own (the Flow runner is built around Flow's network receipts): one prompt at a time; one new conversation per batch, a new one after 15 turns (D-09); the intent is written before the click; a click whose turn does not show up within 30 s, or a new turn that is not our prompt, ends in "needs review" and nothing is sent twice. Anything in the way before the click (no tab, the tab moved to another chat, the user's own text in the composer, image mode not found) pauses the batch and keeps the item; Tiếp tục reopens the batch's conversation. An answer that ends without an image fails the item as `GPT_NO_IMAGE` and pauses the batch. Each finished image is saved at once, while it is still on the page; a later Thử lại takes the tab back to the image's conversation when no prompt is in flight. It writes the same `batch` / `item` / `attempt` rows (`batch.provider = 'chatgpt'`, migration 6), so Hàng đợi, Kết quả and the downloader show ChatGPT batches like any other; the Flow runner skips them (admission, its in-flight count, restart recovery).
- **UI**: Tạo lô gets "Nền tảng: Google Flow | ChatGPT (tạo ảnh)". ChatGPT: images only, no settings, no refs, always sent by the app (the screen says so). Kết nối shows whether a chatgpt.com tab is seen. Hints name ChatGPT instead of Flow for a ChatGPT batch.
- **Limits of this version**: English ChatGPT UI only (the "+" button and the "Create image" item are found by their English labels; another language finds nothing and nothing is clicked); no reference images; no aspect control; not on the Workflow canvas and not in the MCP tools; one ChatGPT tab, one prompt at a time.

The real app window (dev build, real connector, the ChatGPT tab left in the background on purpose): first try paused before the click — the "+" menu does not open in a background tab; fix: the tab is made the active tab of its window before every prompt (`gptFront`), a tab that stays hidden pauses the batch as `GPT_TAB_HIDDEN`. ## Reference images (0.10.0, 2026-11-12)

Measured (Free account, English UI):
- A `paste` event on the editor whose `clipboardData` holds a `File` attaches it; the tile is there 0.2 s later (also for a 6 MB PNG) as `form button[aria-label^="Remove "]`, with `form [role="progressbar"]` ("Uploading …") until the upload ends (4–7 s). The send button is usable before that, so the send waits for the progressbar to go. The "Create image" pill stays, and can even survive a new chat (a restored draft); attachments do not.
- The "+" menu holds more than the tools now (12 entries with plugins) and other buttons appear while the page finishes loading: the first new button is not the menu. The entry is waited for by its label, up to 8 s.
- **Not explained**: three times a paste (or the "+" menu) did nothing for many seconds on a page that had just been opened; twenty other rounds were fine. Seen once in that state: the sidebar read "Loading profile". Built against it: the composer counts as there only without that text, a paste is repeated up to three times when no tile shows after 3 s, and what still fails pauses the batch (`GPT_ATTACH_REFUSED`, `GPT_MODE_NOT_FOUND`) before anything is sent; Tiếp tục starts the prompt over.

Built: `gptAttach { name, mime, b64, clear }`, `gptSend { refs }` (exactly that many tiles, none uploading, or `REF_MISMATCH`); the runner and Tạo lô treat reference images for ChatGPT like Gemini's.

Live: script, two prompts with two reference images each (a 6 MB photo and a colour card): both sent in one conversation and saved (1678x937); the second shows the bell of image one in the blue of image two. Real app: as the second node of a workflow, with the first node's Gemini result as its reference (see the Gemini plan).
